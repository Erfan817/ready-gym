# 智能计划系统：第一条纵向流程

状态：本地规则计划纵向流程已接入正式Android App，版本0.2.0/code3。已实际执行主机Compose交互测试与debug APK构建；尚未真机运行验收、专业审核或接入模型。

## 当前迭代范围

保留已验收的建档卡片布局，改为阳光浅色视觉。新增：

1. 确认基本资料后，补充每周训练天数、每次可用时长、训练经验，以及是否有当前不适或训练限制。
2. 按目标、可用器械与上述条件生成结构化训练草稿，明确生成模式、规则版本、资料来源和待审核状态。
3. 预览每个训练日、动作、目标肌群、组次/时间、休息、要点与估计用时；允许返回修改条件。
4. 用户确认草稿后才能成为本次会话的有效计划，不把查看等同于确认。
5. 缺器械时从已知动作中寻找适配替代项，保持动作模式与目标相近。先显示修改提案，再确认；找不到时明确告知，不捏造替代动作。

## 第一版“智能”的边界

先实现可测试的确定性规则＋动作筛选＋安全约束。界面应明确写“规则计划草稿／未接入大模型”，不能伪装成远端Agent推理，也不能冒充专业评审的医疗或训练处方。真实模型服务、长期记录和练后反馈闭环属于后续接入，不写假接口返回冒充上线能力。GIF按下文的逐动作覆盖提供。

未来模型读取档案和动作候选、解释建议并提出修订，但仍需通过这一层业务校验；模型不能任意编动作、推断用户体能或改写已确认计划。

当前App不联网，模型供应商尚未选择，不能将Hermes自身密钥嵌入APK或擅自用于产品用户请求。接入前单独确认供应商、费用与最小数据授权；服务端保管凭据，客户端只访问业务接口。

## 本轮追加：动作 GIF 与详情

用户明确要求把GIF加入本轮，而不是延后。每个计划动作可打开详情，显示具体动作演示、主肌群、要点与注意事项，开始训练前即可查看。动画支持用户控制播放、暂停/重播，避免多个列表项同时播放。

优先离线打包经许可且与具体动作/变式一致的GIF，记录作者、来源、许可和改动；不因GitHub公开或数据MIT就推断第三方媒体可随意使用。素材获取或匹配不全时，按动作逐项标明缺失，不拿相似动作替代，也不能把首帧图片说成GIF播放已验证。接入接受编译、实际动画解码/控件测试与视觉核对，仍需手机运行验收。

## 下一阶段：真实 AI 接入（用户已要求继续）

当前浅色UI与规则计划完成、测试和APK验收后，继续服务端AI接入，不停在模板系统。流程为：用户授权最小必要档案数据→业务服务读取约束与动作候选→Python服务调用真实模型→返回结构化计划提案→确定性校验→用户预览确认→业务保存/更新。

AI接入完成的验收必须包含一次真实供应商请求、合法结果和无效/超时结果处理；仅写适配器、mock响应或规则回退不算已接入。没有选定供应商或安全提供凭据时，先完成不依赖密钥的工程与契约测试，明确报告阻塞，不冒用Hermes密钥，也不把Token写进APK或仓库。付费额度与模型数据条款仍需用户另行确认。

## 当前UI接入与实际验证

入口为 `MainActivity → ReadyGymTheme → ReadyGymApp`，沿用SunnyTheme浅色palette。建档明确确认后进入训练偏好与安全自述；无不适/无医学限制均不预选。每周2/3/4天、20/30/45/60分钟和初学/恢复/进阶均为单选；进阶返回不支持，不降级。规则草稿有七日选择器、休息日与动作列表、估算时长及来源；详情弹窗调用 `ExerciseDemo(stableId = item.exercise.stableId)`，无remote URL。

确认通过引擎 `confirm` 获取只读快照，与待确认草稿分开保留。重新生成使用新的草稿ID；显示的v序号是本次会话的草稿顺序，底层revision按各草稿/修订对象维护，不用UI序号改写core对象。未再次确认不覆盖当前生效版。缺器械弹窗编辑仅本次可用器械，通过 `replacementCandidates` / `proposeReplacement` 显示候选、无候选或错误，再展示from→to和原计划未改变说明。用户再次明确确认后才采用；连续替换后放弃撤销整轮未确认替换，恢复轮次起始草稿（含完整changes与版本）或原生效计划，不遗留失去比较/取消入口的中间替换。

“身体不适”反馈调用 `evaluateSafety`，非允许路线禁用确认和换动作；实时偏好与已提交反馈按引擎路线取更严格者，新危险输入优先于旧普通不适阻断，已评估的危险状态不会被旧无症状/未填写偏好清除。明确的新安全反馈通过独立反馈提交，不据此作诊断。所有计划仅会话内存；退出、旋转或Activity重建可清空。没有训练日志、自动进阶、持久保存或网络后端。

## 数据与健康边界

优先使用可核验的开源动作元数据；若无法下载，模板资料明确标为自编，不伪造上游ID、中文翻译或来源。图片/GIF许可与数据许可分离，此轮不因计划系统顺便热链未经许可的动图。

身高体重、BMI、性别不直接决定训练负重。经验、可用时长与实际反馈才是安排约束的一部分；未专业评审时不承诺效果或安全认证。

出现当前疼痛、明显头晕、胸部不适、急性受伤等反馈，停止普通计划生成并提示按状况寻求专业评估。系统接收的是用户自述，不是传感器监测，更不是诊断。

权威一般活动建议参考：CDC Adult Activity Overview，https://www.cdc.gov/physical-activity-basics/guidelines/adults.html 。其中150分钟中等强度有氧＋每周至少2天抗阻属于一般指南，不能据此声称本App一次短训练或任何模板已满足所有健康建议。

## 验收清单

- 模板模式在界面明确；草稿生成与确认独立。
- 修改频率、时长、目标或器械能影响符合规则的结果；不是随机拼动作。
- 每个动作ID可查、参数有效、器械条件相符；无候选有可理解错误。
- 显示的时长标明估算，不承诺精确；计划预算不足时不偷偷溢出或挤掉休息。
- 当前风险反馈不进入普通训练流程；无法处理的特殊情况不猜。
- 缺器械替换不会默默改已确认计划，保留版本与原因。
- 测试实际执行，APK实际构建；编译、主机界面测试、设备运行分别说明。
- 本次会话存储与长期保存清晰区分，不默默开始上传身体数据。
